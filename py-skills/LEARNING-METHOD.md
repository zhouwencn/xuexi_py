# Python 模块与依赖学习方法

这套资料的目标不是按字母顺序背 API，而是形成完整能力链：

```text
理解模块解决的问题
  ↓
阅读示例并预测结果
  ↓
模仿示例手写
  ↓
脱离示例独立实现
  ↓
定位并修复错误
  ↓
比较不同方案
  ↓
完成真实任务
```

## API 学习分级

完整 API 索引用来防遗漏，不代表所有接口都要以相同强度记忆。

| 等级 | 学习要求 |
|---|---|
| 核心 API | 不查资料也能正确使用，并能解释参数、返回值和错误边界 |
| 常用 API | 知道适用场景，查一次签名即可正确使用 |
| 低频 API | 知道模块提供这项能力，遇到需求能定位到官方文档 |
| 扩展 API | 理解设计边界，需要扩展、插件或底层控制时再深入 |

## 每个模块的学习动作

1. 先用一句话说明模块解决什么问题。
2. 不运行代码，先预测最小示例的结果和可能异常。
3. 运行示例，修改一个参数并解释变化。
4. 从 API 索引选择一个同类接口进行替换。
5. 制造一个常见错误，阅读异常并修复。
6. 独立完成包含输入、处理、输出和验证的小任务。

## 调试五问

遇到错误时先回答：

1. 当前输入的实际类型和值是什么？
2. 错误发生在调用前、调用中还是返回值使用阶段？
3. API 的参数约束、返回类型和副作用是什么？
4. 是否涉及路径、编码、时区、资源释放、并发或可变状态？
5. 可以怎样构造更小的复现代码？

## AI 辅助学习规则

练习期间建议使用三级提示：

1. 第一次只提示方向，不给完整代码。
2. 第二次指出关键知识点或 API。
3. 第三次只给关键一两行。
4. 明确要求查看答案后，再展示完整参考实现。

AI 给出的 API 名称和参数必须通过本地 API 索引或官方文档核对，不能因为代码看起来合理就直接相信。

## JavaScript 经验迁移

JavaScript 可以帮助建立第一层直觉，但不能简单画等号：

| JavaScript | Python | 主要区别 |
|---|---|---|
| `Array` | `list` | 都是通用序列，但方法、迭代和复制语义不同 |
| `Object` / `Map` | `dict` | 键约束、缺失键处理和迭代结果不同 |
| `JSON.parse/stringify` | `json.loads/dumps` | Python 还区分文件流版 `load/dump` |
| `Promise.all` | `asyncio.gather` / `TaskGroup` | 取消、异常传播和结构化并发语义不同 |
| npm package | Python distribution | Python 的导入包名与安装分发名可能不同 |
| `fetch` | Requests / HTTPX | 超时、连接池、同步/异步和异常处理需要显式设计 |

核心原则：先理解 Python 自身的数据模型、协议和错误语义，再利用已有语言经验类比。

## 通过标准

学习完一个模块后，应能做到：

- 解释它适合和不适合解决的问题。
- 独立完成至少一个真实小任务。
- 正确处理一个正常边界和一个失败边界。
- 在 API 索引中快速找到不熟悉的接口。
- 说明至少两个常见陷阱及其原因。
- 不依赖 AI 也能检查代码是否使用了不存在或已废弃的 API。
